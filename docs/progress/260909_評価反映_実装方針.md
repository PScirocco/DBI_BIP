  `MainWindow.persist_folders()` が `bisim_app.json` に控える。

- シーケンス JSON にも従来どおり `folders` を保存（仕様 3.2 準拠）。開いたシーケンスのフォルダはそのまま採用。

## フェーズ3（実装済み 2026-09-09）

### メモ5: シーケンス名 ↔ ファイル名
- **名前を付けて保存**: 選んだファイル名の stem → `sanitize_name` → `sequence_name`。
  実ファイル名も `<sequence_name>.seq.json` に正規化。
- **保存**: `sequence_name` を `sanitize_name` して `<dir>/<name>.seq.json` へ保存。
  旧ファイル名と違えば**旧ファイルを削除（＝リネーム）**。
- 名前は弾かない・自動変換もしない（`_`・空白・記号の `-` 変換のみ既存どおり。日本語は残る）。
  ②実行ステップに**注意書きラベル**（`steps.name_hint`）を常時表示：
  「シーケンス名・レシピ名は半角英数字推奨。日本語などはファイル名で文字化けの恐れ」。

## フェーズ2（未実装・設計確定）: Stop 情報を Sequence に内包

### 背景（メモ2＋3、担当者の異論を反映）

- 停止（＝Resume）情報は**そのシーケンス固有**。別ファイル（`_resume_*.json`）にすると
  「シーケンス JSON と分離 → 2ファイル管理」の問題が残る。
- → **Sequence JSON が Stop 情報を内包**する。実データ（stat CSV・途中動画）だけ
  出力フォルダ配下のサブフォルダに置き、Sequence がそれを参照する。

### データ構造

`Sequence` に `stops: dict` を追加（キー = NN 文字列）:

```json
{
  "sequence_name": "...", "folders": {...}, "recipes": [...],
  "stops": {
    "01": {
      "recipe_name": "aging01",
      "frames_done": 42, "frames_total": 405,
      "aging_seconds": 12345.6, "is_movie": true,
      "timestamp": "260909-1030",
      "dir": "_stops/<seq>_01_aging01"        // 出力フォルダからの相対
    }
  }
}
```

- `engine.StopState` を `bisim/model.py` へ移動（`Sequence` から参照。`engine` は `model` を import するので
  逆参照を避ける）。`ResumePlan`（numpy を持つ）は `engine.py` のまま。
- チェックポイント実体: `<output>/_stops/<sanitize(seq)>_<NN>_<sanitize(recipe)>/` に
  `stat_r.csv` `stat_g.csv` `stat_b.csv` `deg_r.csv` `deg_g.csv` `deg_b.csv` `movie.mp4`（動画時）。
  ファイル名は素（フォルダ名が識別子）。**日時なし・常に最新1件**。

### フロー

| 場面 | 動作 |
|---|---|
| 停止 → 保存「はい」 | `_stops/<...>/` に書き出し ＋ `sequence.stops["01"] = StopState(...)` ＋ **シーケンス JSON を自動保存**（`_seq_path` があれば。無ければ「名前を付けて保存」を促す） |
| 同じステップを再停止 | `stops["01"]` 上書き、旧 `_stops/<...>/` を削除 |
| 停止 → 保存「いいえ」 | 一時ファイル破棄。`stops` は触らない |
| アプリ再起動 → シーケンスを開く | `Sequence.load` が `stops` を読む → `MainWindow._stopped_states` に反映 → ④で対象ステップ選択時「▶↻ 停止位置から再開」が有効 |
| 停止位置から再開（完了） | `stops["01"]` を削除しシーケンス JSON 再保存 ＋ `_stops/<...>/` 削除 |

### 廃止するもの

- `naming.stop_state_name` と `_resume_YYMMDD-HHMM.json` サイドカー（＋そのテスト）
- メニュー「停止結果を読み込んで再開…」（`MainWindow.load_stopped_and_resume`）
  → 「シーケンスを開く」に一本化
- `write_recipe_outputs(stopped_at=...)` の日時付きフラット出力
  → チェックポイントは `_stops/` サブフォルダへ

### 影響ファイル

- `bisim/model.py`: `Sequence.stops`、`StopState` 移動、`to_dict`/`from_dict`
- `bisim/engine.py`: 停止時の書き出し先を `_stops/`、`ResumePlan` を `sequence.stops` から構築、
  サイドカー廃止、`run_sequence(resume=...)` は現状維持
- `bisim/ui/main_window.py`: `_handle_stopped`（stops 記録＋seq 自動保存）、
  `run_steps("resume")`（sequence.stops から）、`load_stopped_and_resume` 削除、
  再開完了時の後片付け、`open_sequence` で stops → `_stopped_states`
- `bisim/ui/tabs/results.py`: 停止結果の参照パスを `_stops/<...>/` に
- `bisim/naming.py`: `stop_state_name` 削除
- テスト: `test_model`（stops 往復）、`test_engine`（_stops 書き出し・再開）、
  `test_ui`（停止→再起動相当→再開）、`test_naming`（stop_state_name 削除）
- docs: `docs/GUI仕様.md`（7章に stops 内包を追記）、`CLAUDE.md`、`docs/EXEビルド手順書.md`
  （`_resume_*.json` の記述を差し替え）、`docs/実装計画.md`

### 開いたシーケンスを別PCへ持って行った場合

`stops` は残るが `_stops/` 実体が無ければ再開時に「チェックポイントが見つかりません」で失敗
（＝想定内。ローカル状態なので）。`stops` エントリはそのままにして再実行を促す。
