## 変更1（実装済み）: ログのセッション分割

### 決定事項
- アプリ**起動ごと**に新しいログファイル `BISim_YYMMDD-HHMMSS.log` を使う。
- 1ファイルの大きさ感は**従来の日次ログと同程度に保つ**：同一セッション中でもファイルが
  `log_max_mb`（アプリConfig）に達したら `..._02.log` `..._03.log` … と新パートへ継続する。
- 総容量が `log_max_mb` を超えたら古いファイルから削除（`_rotate()`。従来ロジックのまま、
  対象ファイル名が変わっただけ）。

### 実装
- `bisim/logio.py`：`Logger.__init__` でセッションID（`%y%m%d-%H%M%S`）を1回だけ生成。
  `_session_path()` がそのセッション＋現在パート番号からファイルパスを返す。
  `_emit()` は書き込み前に `_advance_part_if_full()` でパート繰り上げを判定してから書く。
  `_rotate()`（総容量削除）は無変更。
- `bisim/tests/test_logio.py`：ファイル名パターンの正規表現チェック、
  複数セッションが別ファイルになること、パート繰り上げの決定的テスト（事前に
  ほぼ上限までファイルを埋めておいてから1行書き込み、パートが進むことを確認）に更新。
- `docs/GUI仕様.md` 6章、`CLAUDE.md` を更新。

## 変更3（実装済み）: AGING_TIME を目標時間として機能させる

### 要望（原文の解釈）
`AGING_TIME` は Aging の**目標時間**を表す：
- 1周回分のAging実時間（fps・フレーム数・ACCEL_RATIO から算出、＝加速込みAging時間）が
  `AGING_TIME` を**超える** → `AGING_TIME` に達した時点で打ち切り
- 1周回分が `AGING_TIME` に**満たない** → 最後まで実行した上で、**同じ入力を繰り返して**
  不足分の時間を埋める（＝動画をループしながら劣化計算を継続）

### 決定事項（担当者確認済み）
- `AGING_TIME` の単位は**秒**。UIは整数秒でよい（小数精度は不要）。
- 目標時間に満たず繰り返す場合、**出力動画は全周回を1本に連結して出力**する
  （倍率が大きいと動画・処理時間が線形に増える点は許容する）。
- 静止画（PQ評価、dt=0）は対象外（現状どおり Aging時間への寄与ゼロ）。

### アルゴリズム（フレーム境界でのみ判定。境界を跨いだ超過は許容）

```
dt_accel = dt(=1/fps) × ACCEL_RATIO   # 1フレームあたりの加速込み秒数
target   = sim_param["AGING_TIME"]     # 秒
i = start（絶対フレーム番号。継続/再開に対応）
loop:
    if control.stopped: break
    フレーム i の画像・ヒートマップを読む
      → native動画終端に達したら位置を0へシークして周回
        （ヒートマップも同様に周回。両者のフレーム数が異なる場合の同期は非対応のまま=現状の制約を踏襲）
    劣化計算・出力動画へ書き込み・aging_seconds += dt_accel
    i += 1
    if aging_seconds >= target: break     # 満了 → 打ち切り
```
- 判定は**1フレーム処理し終えた後**に行う（退化防止：`AGING_TIME` が1フレーム分の
  `dt_accel` より小さくても、最低1フレームは処理してから打ち切る）。
- `dt_accel<=0`（fps/ACCEL_RATIOが不正）等の異常系は無限ループにしないガードが必要。

### 追加の決定事項（実装時）
- **既定値の変更**：`DEFAULT_SIM["AGING_TIME"]` を `10.0`（旧・未使用時代のプレースホルダ）から
  **`0.0`** に変更。`0` は「無制限＝従来どおり動画を1周回のみ処理」を意味し、
  ユーザーが明示的に正の値を設定するまでは既存の挙動と完全に同じになる
  （新規レシピが突然短時間で打ち切られる事故を防ぐための安全側デフォルト）。
- `RunResult.frames_total` は動画の場合のみ「AGING_TIME 由来の目標フレーム数」に変更
  （静止画は従来どおり `1`）。`0`＝無制限のときは入力動画の実フレーム数のまま（従来と同じ値）。

### 実装
- `bisim/model.py`：`DEFAULT_SIM["AGING_TIME"]` を `0.0` に変更（コメントで意味を明記）。
- `bisim/engine.py`：`run_recipe` の動画ループを `range(start,end)` の一発読みから、
  絶対フレーム番号（`frame_idx`）を進めながら
  - `use_target = dt_accel>0 and AGING_TIME>0` のときだけ動画終端で `POS_FRAMES=0` に
    シークして周回を続ける（`use_target=False` なら従来どおり終端で打ち切り）
  - 1フレーム処理後に `aging_seconds >= target` を判定して打ち切る（最低1フレームは処理する）
  - `resume_from`（`start`）が動画の実フレーム数を超える場合は `start % frames_total` で
    実動画上のシーク位置を求める（周回をまたいだ再開に対応）
  という形に書き換え。`frames_target = start + ceil((AGING_TIME - 現在のaging_seconds) / dt_accel)`
  を計算し、動画のときの `RunResult.frames_total` に採用。
- `bisim/ui/tabs/step_config.py`：`AGING_TIME` スピンボックスを整数秒精度に（`_dspin` に
  `decimals` 引数を追加）。
- `bisim/ui/i18n.py`：ラベルを「AGING_TIME（現状未使用）」→「AGING_TIME [秒]（目標Aging時間。0=無制限）」に変更。
- テスト：`test_engine` に5件追加（既定0=無制限の確認、打ち切り、周回連結、
  周回をまたいだ停止→再開、シーケンス継続）。`test_paramio`（`DEFAULT_SIM` のCSV書式が変わった分）、
  `test_ui`（AGING_TIMEフィールドの既定値・精度・収集）を更新。
- `docs/GUI仕様.md`（5-③に確定仕様を追記）、`docs/理解と方針.md`（`bisim/engine.py` 側の実装状況を追記。
  `source/` 側は無改変・未使用のまま）、`CLAUDE.md`、`docs/実装計画.md` を更新。
