## 変更1（実装済み）: ログのセッション分割

### 決定事項
- アプリ**起動ごと**に新しいログファイル `BISim_YYMMDD-HHMMSS.log` を使う。
- 1ファイルの大きさ感は**従来の日次ログと同程度に保つ**：同一セッション中でもファイルが
  `log_max_mb`（アプリConfig）に達したら `..._02.log` `..._03.log` … と新パートへ継続する。
- 総容量が `log_max_mb` を超えたら古いファイルから削除（`_rotate()`。従来ロジックのまま、
  対象ファイル名が変わっただけ）。

### 実装
- `bisim/logio.py`：`Logger.__init__` でセッションID（`%y%m%d-%H%M%S`）を1回だけ生成。
  `_session_path()` がそのセッション＋現在パート番号からファイルパスを返す。
  `_emit()` は書き込み前に `_advance_part_if_full()` でパート繰り上げを判定してから書く。
  `_rotate()`（総容量削除）は無変更。
- `bisim/tests/test_logio.py`：ファイル名パターンの正規表現チェック、
  複数セッションが別ファイルになること、パート繰り上げの決定的テスト（事前に
  ほぼ上限までファイルを埋めておいてから1行書き込み、パートが進むことを確認）に更新。
- `docs/GUI仕様.md` 6章、`CLAUDE.md` を更新。

## 変更2（実装済み）: ヒートマップなし＝パネル全面固定温度

### 決定事項
- ③ステップ設定にチェックボックス「ヒートマップなし（パネル全面を固定温度）」＋
  数値入力（℃、`TMP_L`/`TMP_H` と同じ範囲）を追加。
- チェック時はヒートマップのファイル欄を無効化し、ヒートマップファイルは不要（未指定でよい）。
- `source/main.py` は**無改変**の方針を維持するため、固定温度は
  「その回だけ `TMP_L`＝`TMP_H`＝固定温度としてモデルに渡す」ことで実現する。
  `temp_update_stat_and_burn_img` は `ht[:,:,0]` を `TMP_L`〜`TMP_H` の間で線形補間して温度を作るが、
  `TMP_H-TMP_L=0` なら ht の中身に依らず定数（＝固定温度）になるため、ヒートマップ画像・動画を
  一切読まずに済む（ダミーの ht 配列を1つ用意して使い回すだけ）。

### 実装
- `bisim/model.py`：`Recipe` に `heatmap_mode`（`"file"` / `"fixed"`）・`fixed_temp_c`（既定 25.0℃）を追加。
  `HEATMAP_MODES` 定数、`validate()`／`to_dict()`／`from_dict()` 対応（不正値は `"file"`/25.0 にフォールバック）。
- `bisim/engine.py`：`run_recipe` で `heatmap_mode=="fixed"` のとき
  - ヒートマップのパス存在チェック・読込（`imio.imread` / `cv2.VideoCapture`）をスキップ
  - `sim = dict(recipe.sim_param)` をコピーし `sim["TMP_L"] = sim["TMP_H"] = fixed_temp_c` に上書きして
    `model.update()` に渡す（`recipe.sim_param` 自体は変更しない）
  - 静止画・動画とも、ht 引数には中身を問わないダミー配列（`np.zeros`）を使い回す
- `bisim/ui/tabs/step_config.py`：チェックボックス＋温度スピンボックスを追加。
  トグルでヒートマップ欄の有効/無効を切替、プレビューを「固定温度 XX℃」表示に置換。
  値の確定は他のパラメータと同様「この設定を適用」ボタン経由（`_collect_into_recipe`）。
- `bisim/ui/main_window.py`：実行前チェック（`input_image`/`heatmap` 必須）を
  `heatmap_mode` に応じて分岐（`fixed` のときは heatmap 不要）。
- テスト：`test_model`（Recipe往復・バリデーション・不正値フォールバック）、
  `test_engine`（固定温度での静止画/動画 `run_recipe`、温度マップが定数になることを確認）、
  `test_ui`（③タブのチェックボックス操作、ヒートマップファイル無しでの実行 end-to-end）。

## 変更3（未着手・設計）: AGING_TIME を目標時間として機能させる

### 要望（原文の解釈）
`AGING_TIME` は Aging の**目標時間**を表す：
- 1周回分のAging実時間（fps・フレーム数・ACCEL_RATIO から算出、＝加速込みAging時間）が
  `AGING_TIME` を**超える** → `AGING_TIME` に達した時点で打ち切り
- 1周回分が `AGING_TIME` に**満たない** → 最後まで実行した上で、**同じ入力を繰り返して**
  不足分の時間を埋める（＝動画をループしながら劣化計算を継続）

### 決定事項（担当者確認済み）
- `AGING_TIME` の単位は**秒**。UIは整数秒でよい（小数精度は不要）。
- 目標時間に満たず繰り返す場合、**出力動画は全周回を1本に連結して出力**する
  （倍率が大きいと動画・処理時間が線形に増える点は許容する）。
- 静止画（PQ評価、dt=0）は対象外（現状どおり Aging時間への寄与ゼロ）。

### アルゴリズム（フレーム境界でのみ判定。境界を跨いだ超過は許容）

```
dt_accel = dt(=1/fps) × ACCEL_RATIO   # 1フレームあたりの加速込み秒数
target   = sim_param["AGING_TIME"]     # 秒
i = start（絶対フレーム番号。継続/再開に対応）
loop:
    if control.stopped: break
    フレーム i の画像・ヒートマップを読む
      → native動画終端に達したら位置を0へシークして周回
        （ヒートマップも同様に周回。両者のフレーム数が異なる場合の同期は非対応のまま=現状の制約を踏襲）
    劣化計算・出力動画へ書き込み・aging_seconds += dt_accel
    i += 1
    if aging_seconds >= target: break     # 満了 → 打ち切り
```
- 判定は**1フレーム処理し終えた後**に行う（退化防止：`AGING_TIME` が1フレーム分の
  `dt_accel` より小さくても、最低1フレームは処理してから打ち切る）。
- `dt_accel<=0`（fps/ACCEL_RATIOが不正）等の異常系は無限ループにしないガードが必要。

### 影響見込み
- `bisim/engine.py`：`run_recipe` の動画ループを「`range(start,end)` 一発読み」から
  「絶対フレーム番号＋周回対応の while ループ」に書き換え。
  `RunResult.frames_total` の意味が「入力動画の実フレーム数」→「AGING_TIME 由来の目標フレーム数
  （進捗バー用の目安値）」に変わる。`resume_from` が動画の周回をまたぐケース
  （`start % native_frames_total` でシーク）に対応が必要。
- UI側（`RunTab`／停止・再開ダイアログ）は `frames_total` の意味変更にそのまま追従できる想定
  （表示コードの変更は最小限のはず）だが、実装時に要確認。
- テスト：短い動画×小さい `AGING_TIME` で打ち切り、短い動画×大きい `AGING_TIME` で周回連結、
  停止 → 周回をまたいだ位置からの再開、を新規に追加する必要がある。
- `docs/GUI仕様.md`（`AGING_TIME` を「未使用」から確定仕様へ）、`理解と方針.md`、`CLAUDE.md`、
  `docs/実装計画.md` を更新。

この変更は3件の中で最も規模が大きく（`run_recipe` の中核ロジック・境界条件のテストが多い）、
今回のセッションでは着手していない。次回、上記アルゴリズムをベースに実装する。
