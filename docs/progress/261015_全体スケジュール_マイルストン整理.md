## 3. 理論モデルの設計変更と bisim への影響

### ① 温度依存を「β側」から「ストレス累積側」へ（10/2 改訂、10/8 MTG で説明済み）

- **変更内容**：劣化率は「温度に依存しない基準カーブ」（固定のβ₀）から求める。温度依存は
  **ストレスの累積計算だけ**に入れる（K(temp)：アレニウス型＋βの温度差による換算項）。
  - 理由：βに温度依存があると、同じストレス量でも高温ほど劣化率が大きく出て、
    **低温に戻すと回復したように見える**（物理的に不自然）。
- **現行 bisim での実態**：`engine.MasterModel.deg_maps()` は `β = B0 + A·temp_kelvin` で劣化率を計算しており、
  `run_recipe` は deg を計算するために「最終フレームの温度マップ」（`RunResult.temp_kelvin`）を保持している。
  → **今のツールでは、PQ評価ステップのヒートマップ温度を変えるだけで劣化率が変わる＝まさに指摘されている不自然な挙動が出る**。
- **影響**：`DegradationModel` の I/F（`update()` で累積、`deg_maps()` でマップ算出）はそのまま使える。
  ただし `deg_maps()` は温度を使わなくなるので、`temp_kelvin` の受け渡しは不要（残しても実害はない）。
  「累積時間マップ」の意味は「基準条件に換算したストレス時間」となり、今の表記のままでよい。
- **未解決**：**劣化後の温特**（温度による可逆的な輝度変化）をどう扱うかは継続検討（10/8）。
  温特補正（HeatMapを使ったGamma補正）を入れる場合、DBIとの重複補正にならない配慮が必要で、
  **PQ評価ステップでも温度入力が要る可能性**がある。

### ② BC設定の仕様変更（`劣化Simulator_CorePart進捗.pptx`、10/15）

- `bcsetting.csv`：`ABL_LIMIT` を追加。DBV関連の変数は削除（内部変数にする）。**15Band分の VI-LUT
  （R/G/B × 0〜255階調 → 電流。各色のHBM電流=1で正規化）＋各Bandの輝度・Duty の表**を持つ。
- `simconf.csv`：`PEAK_L`（目標のPeak輝度）を追加。DBVではなくPeak輝度で設定し、隣接Bandを線形補間する。
- **現行 bisim での実態**：**BC設定はまだ配線されていない**（`MasterModel.update()` は `bcset_dict={}` を渡しており、
  `Recipe` にもUIにもBC設定の欄がない。`paths.py` に既定フォルダ `bcset` があるだけ）。
- **影響**：既存CSVの書式を変えるだけでは済まず、**新しい入力種別の追加**になる。
  `Recipe` のフィールド、③ステップ設定タブの入力欄、`naming` の種別トークン（例 `bc-setting`）、`paramio` の読み書きが必要。
  VI-LUT は表（15Band×3色×256）なので、③タブでインライン編集はせず**ファイル参照**にするのが現実的。
- **未解決**：Sig→電流の予測方法（Band間の補間ルール）、補正値を本線に戻す方法（①②③案）は松井氏が検討中。

### ③ その他、コアに入る予定の要素（`Proposals for DBI model`）

- Duty依存、**Peak target 低減機能（βp。式はTBD）**、パネル間の電流効率ばらつき（gadj）。
  → BC設定・モデルパラメータの入力項目が今後さらに増える可能性がある。
  **入力パラメータの一覧（何をどのファイルで持つか）をコア受領時に松井氏と確定する**とよい。

### ④ Heat Map（礒部モデル）

- 礒部氏が**温度マップ推定モデル（簡易モデル rev2、HW実装仕様＋Cリファレンス）**を開発中。
  画像（階調→電流）から **10×20 ブロックの温度 → 画素単位の温度 [℃]** を出力する。
  10/8 時点で **Heat Map 動画の作り方は 3案（サーモ実測／計算／計算＋実測）で継続議論**。
- 礒部資料に「焼き付きの累積損傷は輝度マップ×温度マップ（10×20）で積算する」「E_a = 0.5 eV なら
  25℃→45℃で劣化速度が約3倍」とあり、温度の効き方は**①の新しい累積側の温度依存と同じ形**。
- **影響【推定】**：将来は「動画ファイルとしてのヒートマップ」ではなく、**入力画像から温度マップを自動生成する**
  経路（Platform Concept の「Heat Map gen」ブロック）が必要になる。bisim の
  `heatmap_mode`（現状 `file`/`fixed`）に、モデル生成の第3モードを追加できる形にしておくのが自然。

### ⑤ プラットフォーム全体像（`Platform Concept`）

- 最終形は、**Burn-in sim の前段に DBI / BIP / Heat Map gen を挟み**、
  「補正あり／なしの Aging Step → PQ評価 Step → 劣化後画像の比較」を行う構成。
- DBI は最初、逐次補正をせず**DBI内部の劣化累積計算だけ**で最適化を進める（簡易化）。
- **影響【推定】**：bisim のシーケンスに「前処理（DBI/BIP/HeatMap gen）」を差し込めるようにしておくと、
  BIP Phase2 や DBI 評価で使える。現時点ではスコープ外だが、2027年1Q の本格運用前に要否を確認したい。
