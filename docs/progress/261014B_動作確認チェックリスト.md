## D. 2026-10-14 追加対応（評価メモ・AGING_TIME挙動の調査）

担当者から「AGING_TIMEを10秒→20秒に変えても結果が変わらない」との報告を受け、
提供いただいたログ（`eval_test/BISim_261014-132841.log`）を解析して原因を特定した。

| # | 内容 |
|---|---|
| 原因 | ACCEL_RATIO=30000（既定値）・30fps では、1フレームあたりの加速込み時間が**約1000秒**になる。AGING_TIME=10秒・20秒はどちらもこれより短いため、「最低1フレームは処理する」という仕様（AGING_TIMEが極端に短くても0フレームで終わらせないための安全策）により**どちらも同じ1フレームだけ処理**され、結果が完全に一致していた。**バグではなく、ACCEL_RATIOとAGING_TIMEの粒度の関係による制約** |
| 対応 | ④実行タブの動画情報表示に**見積りフレーム数**を追加。例：「設定中の AGING_TIME = 00h 00m 20s → 1周回の途中で打切り（約1フレームで終了）」。AGING_TIMEを設定する前に、何フレーム処理されるかが事前に分かるようにした |
| 備考 | 意味のある差を見るには、AGING_TIMEを「1フレームあたりの加速込み時間」（既定値なら約1000秒＝約17分）以上の単位で変える必要がある |

テスト：`test_engine.test_aging_time_small_values_round_up_to_same_frame_count` で
この条件（ACCEL_RATIO=30000, AGING_TIME=10秒/20秒, 固定温度100℃）が再現すること、
および新しい見積り表示が正しいことを確認。selftest 74/74 pass。
