## 2. 今回デバッグした3件（実機評価で発覚・解決済み）

いずれも `docs/progress/261014B_動作確認チェックリスト.md` D章に詳細あり。

1. **累積時間マップのRGB合成で反転が見えにくい**
   → 原因：R/G/B共通の最大値で正規化していたため、値の大きい色に引っ張られていた
   → 対応：`bisim/ui/tabs/results.py::_MapView.reload()` で**色ごとに自分の最大値**で正規化
2. **Aging時間表示が小さい値（秒規模）だと「0.00 h」に見える**
   → 対応：`engine.format_aging()` を時:分:秒表示に変更（`format_aging(10)` → `"00h 00m 10s"`）
3. **AGING_TIMEを10秒→20秒に変えても結果が変わらない**（担当者が実機ログで報告、重要な調査）
   → 担当者提供の `eval_test/BISim_261014-132841.log` を解析して特定：
     既定 ACCEL_RATIO=30000・30fps では **1フレーム＝約1001秒**。AGING_TIME=10秒/20秒は
     どちらもこれ未満なので「最低1フレームは処理する」ルールに丸められ、**同じ1フレームだけ**
     処理されて結果が一致していた。**バグではなく仕様上の粒度の制約**
   → 対応：`engine.aging_time_add_frames()` を新設（`run_recipe` 本体と共有）、
     ④実行タブに選択ステップの動画情報＋見積りフレーム数を表示する機能を追加
     （`bisim/ui/tabs/run.py::_update_movie_info()`）。これで「設定中のAGING_TIME → 無制限／
     1周回の途中で打切り（約Nフレームで終了）／周回連結（約N周回ぶん、約Mフレーム）」が事前に見える
   - 調査の過程で `engine.MasterModel()` を直接叩く再現スクリプトを多数作成（`/tmp/repro_*.py`。
     セッション終了時に残っていれば消してよい一時ファイル）。**この種の「実機でだけ起きる」報告は、
     まず純粋なエンジン呼び出しで数値を再現し、合わなければGUI層（SimWorker経由）で再現、
     それでも合わなければ実機ログを見せてもらうのが効率的**（今回もこの順で特定できた）

## 4. フェーズF（コア統合）に向けて覚えておくこと

`team/Meeting/` の松井氏資料（`Proposals for DBI model_v.0.0.0_261002.pptx`、
`劣化Simulator_CorePart進捗.pptx`）から、将来コア差し替え時に影響しそうな点：

- **劣化モデルの温度依存の入れ方が変わる予定**：現行モデル（`source/main.py`）はβ（拡張指数のべき指数）に
  温度依存を持たせているが、これは「高温→低温に戻ると劣化が回復したように見える」という不自然な挙動を生むため、
  **β側ではなくストレス累積側に温度依存を入れる**方向に修正される見込み。コア差し替え時、
  `DegradationModel.update()`/`deg_maps()` のI/F（1フレーム更新＋劣化率マップ算出）自体は変わらない想定だが、
  中身の計算は変わる
- **入力CSVの仕様が変わる可能性**：`bcsetting.csv` に `ABL_LIMIT` 追加・DVB関連変数の一部削除・
  15Band分のVI-LUT＋Duty設定化、`simconf.csv` に `PEAK_L`（DBVではなくPeak輝度で設定）追加。
  `bisim/paramio.py` のCLI互換CSV読み書きが影響を受ける可能性がある。コア受領時に実物のCSVを見て確認すること
- 目標Aging時間の実例は**500h〜1000h規模**（秒換算すると180万〜360万秒）。既定ACCEL_RATIOでの
  見積りフレーム数表示（今回追加）はこの規模感でも実用になるはずだが、実際にコアが来たら一度確認したい
- 礒部氏がHeat Mapの物理予測モデル（画像contentから温度分布を予測）を開発中。将来bisimの
  「ヒートマップ入力」を自動生成する経路になり得る（今は動画ファイルを直接与える形のみ対応）

## 6. 作業時の注意点（今回判明した実務的なコツ）

- **pip がこの環境では社内ミラー設定が壊れている**。グローバルインストールする必要がある場合は
  `pip install --isolated --index-url https://pypi.org/simple <pkg>` で回避できる（`openpyxl` / `pandas` /
  `python-pptx` はこの方法でこのセッション中にインストール済み。`.venv` に入っているはず）
- Excelファイル（`docs/review/*.xlsx`）を編集する際は、`openpyxl` で既存の書式（フォント・枠線・塗り・
  列幅）を `copy.copy()` でテンプレート行から引き写すこと。セルを**結合すると非アンカーセルの書式が
  Excel上で描画に反映されない**ことがあるため、帯状の見た目が欲しいときは結合せず、隣接セルを個別に
  同じ書式で揃える方が安全（今回この問題に当たって結合をやめた）
- `.seq.json` のフォルダ優先度（開いたシーケンス自身の`folders`が直近フォルダ設定を上書きする仕様）は
  3パターンで再現検証したが問題が見つからなかった。担当者の最終報告では解決扱い（OK）になっているが、
  **原因不明のまま「直った」ことになっている点は一応留意**（再発したら `docs/progress/261014B_動作確認
  チェックリスト.md` A-2の経緯を参照）
