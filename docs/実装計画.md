## 新セッションでの開始手順

1. この `docs/実装計画.md` と `docs/GUI仕様.md` を読む（`CLAUDE.md` は自動読み込み済み）
2. 下の「フェーズ区切り」表で**次に着手するフェーズ**を確認（`未着手` の最上段）
3. そのフェーズが `prototype/` から移植する場合は該当ファイル（`tabs.py` / `i18n.py` / `widgets.py` など）を読む
4. `python -m bisim.selftest` を実行し、既存が**全 pass** することを確認（現状 49/49）
5. 該当フェーズの T タスクを上から実装。各 T にテストを追加
6. フェーズ完了＝「全チェックボックス `[x]` ＋ selftest 全 pass ＋ git commit」→ この表を更新

打つ指示の例：`docs/実装計画.md の次のフェーズから実装を進めて。手順は冒頭のとおり。`

---

## 方針

- 本番は新パッケージ **`bisim/`** として作る。`prototype/` から**流用できる部分は移植**、状態モデル・I/O・エンジン境界は**作り直す**。
- ボトムアップで実装（モデル → 命名 → エンジン → ログ → UIシェル → タブ → 状態遷移 → パッケージング）。各段階で単体確認できる形にする。
- `source/` は無改変。劣化コアは `bisim/` から**差し替え可能なI/F**越しに呼ぶ。
- モデル/Simパラメータの CSV 書式は `source/load_com_info.py` と**完全互換**を保つ（IP設計者がCLIで独立に使えるように）。

### `prototype/` からの移植可否

| 流用する | 作り直す |
|---|---|
| `i18n.py`（文言はレビュー反映）／ `imio.py` ／ `widgets.py`（ImagePanel, MplCanvas）／ `apply_light_theme` ／ 各タブのレイアウト骨格 | `state.py` → レシピ/シーケンス/3Config ／ `sim_runner.py` → `engine.py`（正式I/F） ／ 出力ファイル名（連番 → 命名規則） ／ 実行制御（中断のみ → 中断・再開＋停止） |
