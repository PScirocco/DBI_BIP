## 1. 背景と用語

### OLED焼き付き（Burn-in / Image Sticking）とは

- OLEDは画素（R/G/Bサブピクセル）ごとに電流を流して発光する。
- 有機発光材料は**電流を流して光らせた分だけ効率が落ちる**（＝同じ電流でも時間とともに暗くなる）。
- 明るいほど・温度が高いほど速く劣化。色ごとに速度が違う（一般に青が弱い）。
- ロゴ・時刻表示・字幕帯など「いつも同じ場所が明るい」部分だけ余計に劣化し、
  その部分が暗く・色ずれした状態が恒久的に残る ＝ 焼き付き。
- 隣接画素の劣化差が「輝度ムラ」「色度シフト（Δu'v'）」として見える。

### 対策の2方向

| 略語 | 意味 | 考え方 | 例 |
|---|---|---|---|
| **BIP** (Burn-In Prevention) | 予防 | 焼き付く前にストレスの偏りを減らす | ロゴ部を減光、ピクセルシフト、静止画検出で全体減光 |
| **DBI** (De-Burn-In) | 補正 | 劣化した画素を明るめに駆動して見かけの輝度差を打ち消す | 各画素の劣化量を推定 → 補償ゲインをかける |

いずれもパネル／ドライバICの中の処理（IP = 回路ブロック設計）。IPハード設計者の担当。

### なぜシミュレータが必要か

実パネルでの焼き付き試験は数百〜数千時間かかる。DBI/BIPのパラメータを1つ変えるたびに
実機で待てない。そこで「この映像をこの条件で表示し続けたら何時間後にどれだけ劣化するか」を
計算で予測する。加速機能で数千時間を数分に短縮。
DBI/BIP「あり／なし」で同じ映像を通し、劣化後画像を比較して効果を定量評価する。

### 用語ミニ辞典

| 用語 | 意味 |
|---|---|
| Aging | 意図的に通電して劣化させること（劣化試験） |
| PQ | Picture Quality（画質） |
| DBV / NIT | NIT=輝度単位(cd/m²)、DBV=ドライバの明るさ設定値 |
| Duty | PWM調光のオン時間比率 |
| γ（ガンマ） | 画素値と実輝度の非線形関係。輝度 ≈ 画素値^2.2 |
| Heat Map | パネル面内の温度分布をグレースケール画像で表したもの |
| demura | 表示ムラ補正 |
| Δu'v' | 色度座標のずれ量。0.01超で色ずれが目立つ |
| τ（タウ） | 劣化の時定数（半減寿命と相関）。コードの K0 が相当 |
| Master Model / Sub Model | 全体の劣化式 / BC条件ごとの補正LUT（Sub Modelは未実装） |
| Δη₁, Δη₂ | 資料1の劣化2成分モデル。現コードは1成分に簡略化 |

## 2. 資料の内容

### 資料1: AMOLED_Image_sticking_prevention_compensation_v01.pptx（2018, Matsui）

DBI補正アルゴリズムの理論。TV・医療用ディスプレイで量産実績のあるモデル。

- **スライド3**: 焼き付きとは。隣接画素のストレス差 → 均一性喪失・色度シフト。
  TV用途では画素間のストレス差は ×1.5〜×2 程度。
- **スライド4（Modeling ①）**:
  - 劣化は (時間 × 電流) の2次元履歴で決まる。時計の時間だけでは決まらない。
  - 各画素の劣化を**2成分 Δη₁, Δη₂ の重み付き和**で再現。測定は2〜3の基準条件だけ。
  - 劣化後の「電流→輝度」カーブから**補償ゲイン**を算出（= 目標輝度を出すのに必要な電流の比）。
- **スライド5（Modeling ②）**:
  - 運転時間を**基準電流 Iref 換算のストレス時間**に変換: `t_eq = Σ Δt·(I/Iref)ⁿ`（n=加速係数）。
  - Iref基準の劣化量（Δη₁）が同じなら Δη₂ は電流パスによらずほぼ同じ
    → 信号履歴を1つの数字にまとめられる（近似）。残差は補正項 S(Istress, Iref)。
- **スライド6（Modeling ③）**: 補償駆動で劣化が過度に加速 → 補正failure。
  動作時間に応じてピーク輝度を下げる（target curve）ことで過剰劣化を抑制。
- **スライド7-8**: 補償システム概要（Stress蓄積→Gain計算→γ/γ⁻¹→WB調整→demura+、DDR/Flash）。
  TV/医療用は全画素のstressデータ保存・全画素補正。スマホ用は簡略化・圧縮が必要（次テーマ）。

### 資料2: Platform Concept for DBI & BIP development.pptx（2026.07.21, Matsui & Isobe）

シミュレータ＋DBI/BIPを組み合わせた開発支援プラットフォームの構想。

- **Burn-in simulator の入出力**
  - Input 5種: [1] Input Image（動画=Aging用 / 静止画=焼き付き画像生成用） [2] Heat Map
    [3] BC setting（DBV_NIT, Duty） [4] Degradation model parameters（実測から抽出）
    [5] Sim conditions（Aging time, 加速設定, 温度）
  - 内部: conv_lum2str（輝度→ストレス）→ Δstress → Total stress += Δstress
    → deg1/deg2 Calc.（劣化計算）→ γ⁻¹
  - Output 3種（RGB別）: [1] Degradation Image（焼き付き画像） [2] Degradation Map（劣化率, csv）
    [3] Total Stress Map（csv, Load/Saveで途中再開可能）
  - 動画×Nサイクル、温度＆Duty依存、劣化加速でSim時間短縮
- **Use-Case（スライド3）**: DBI開発・BIP開発をそれぞれ2ステップで実施
  - Step1 Aging Step: 映像をDBI/BIPに通す →（補正後映像＋HeatMap）→ Burn-in simulator
    → Total Stress Map。比較用にDBI/BIPなしの経路も回す。
  - Step2 PQ Evaluation Step: 蓄積ストレスから劣化後画像を生成し、あり／なしを比較。

### main.py の引数（`eval_exec.bat` 参照）

```
python main.py <input_img> <heatmap> <bcset.csv> <degparam_mm.csv> <degparam_sm(未使用)> \
               <simconf.csv> <stat_r_ini> <stat_g_ini> <stat_b_ini> <ini_en> <oe(未使用)> <idx>
```

- `input_img`: `.mp4`=動画（`process_type="mov"`） / `.png`=静止画（`"img"`）
- `ini_en=1`: `stat_*_ini` を読み込んで**途中の劣化状態から再開**
- `idx`: 出力ファイル名の prefix

### 劣化モデル式

```python
# 温度: ヒートマップ画素値 → 温度 [K]
temp = (ht[:,:,0]/255) * (TMP_H - TMP_L) + TMP_L

# 劣化率（輝度残存率, 1.0=劣化なし）: ストレッチ指数関数
deg  = exp( -( stat ** (B0 + A*temp) ) )

# 劣化画像生成: 線形輝度に変換 → deg倍 → ガンマに戻す
lum  = (img/255)**2.2 * deg
img  = 255 * lum**(1/2.2)

# ストレス累積（＝ Iref換算ストレス時間 t_eq）
stat += tsample * ACCEL_RATIO * lum**N / (K0 * exp(Q/temp))
```

| コードの項 | 資料での意味 |
|---|---|
| `lum ** N` | (I/Iref)ⁿ — 信号レベルの加速係数（スライド5の時間軸伸縮） |
| `K0` | τ₀·Irefⁿ — 基準の時定数。Iref を畳み込み済み（注記 `K0 = τo·(DBV_MAX·1/duty_max)^n`） |
| `exp(Q / temp)` | 時定数 τ の温度依存（アレニウス型） |
| `ACCEL_RATIO` | シミュレーション時間短縮のための加速。数式的には Iref 換算と同じレバー |
| `stat`（累積結果） | t_eq — Iref・基準温度に換算した正規化ストレス時間 |
| `deg` | Δη₁ に相当する1本の基準劣化カーブ（β = B0 + A·T） |

### 設定ファイルの現在値

- `degparam_mm.csv`（N, K0, Q, B0, A × R,G,B、暫定ダミー）:
  N=[1.5,1.3,1.7], K0=[500,1000,100], Q=[1000,800,600], B0=[0.7,0.8,0.4], A=[0,0,0]
- `simconf.csv`: AGING_TIME=10, ACCEL_RATIO=30000, TMP_L=25℃, TMP_H=60℃
- `bcsetting.csv`: DMP_GAIN=1, DBV_NIT_CURR=0.6, BC_U=0.8, BC_L=0.5, DUTY全部=1

  モデル式は今後変わる前提。GUI/IO/可視化はモデルに依存しない層として作る。
- 現コードのグローバル変数・固定ファイル名・`sys.argv` 前提・`except:` 握りつぶしは
  GUI化の前にリファクタリングが必要。
