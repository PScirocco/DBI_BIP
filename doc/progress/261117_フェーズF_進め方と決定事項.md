### 手順5 の結果（2026-11-18 区切り3：5-4 ⑤タブ・5-5 の残り）

- ⑤「輝度残存率マップ」（`ui/tabs/results.py::_MapView`）
  - 「表示する量」の選択ボタン：deg1（基準電流密度）／deg2（サブモデル）／deg1×deg2（画像にかけた値）。既定は deg1。
    deg1×deg2 は表示時に `deg_{c}.csv × deg2_{c}.csv`（ファイルは増やさない）
  - deg2 の無い結果（`has_deg2`。フェーズF より前の停止結果）では deg2 系のボタンを押せず、deg1 に戻し、注記を出す。
    ※ ⑤の結果は実行（完了・停止）のときだけ作られ、再開して完了すると deg2 が出力されるので、実際に deg2 の無い結果が出ることはほぼ無い
  - スケールの切り替えを輝度残存率マップにも付けた：「0 〜 1（1 超は 1）」（既定）／「面内最小 〜 面内最大」（3つの量とも共通）
  - **黒の画素**：deg2・deg1×deg2 では、最後に処理した入力フレームでその色が 0 の画素を灰色で表示し、表示範囲と統計から除く。
    カーソル値には「（黒の画素）」を付ける。RGB合成では、黒の色成分をその画素で光っている色の平均で埋める（全色黒は灰色）。deg1 は除かない
  - 黒の画素はエンジンが求める：`engine.black_mask_bgr`、`RunResult.input_black`（コアが入力を書き換える前のコピーから。ファイルには出さない）→
    `ResultEntry.input_black`。最初は「出力の最後のフレームが 0」で判定したが、劣化で黒くなった画素も入ってしまうためやめた
  - ボタンの下に注記（選んだ量の意味、deg1×deg2 のずれ、黒の画素の数）
  - マップの見出しを2行に（1行目＝何のマップか、2行目＝表示範囲）。英語表示で左右が切れていた件（10/28）もこれで解消
- 確認：selftest **120/120**（新規2本：deg2 の無い結果でボタンが押せないこと、deg2・deg1×deg2・スケール・黒の画素・言語切替。
  既存の end-to-end と deg2 出力のテストに deg1×deg2 と `input_black` の確認を追加）。松井さんの 11 ケースは差 0 のまま
- 確認用シーケンス `bisim2/eval_test/phaseF_check/phaseF_check.seq.json`（3色円の Aging 1h → PQ評価 白 → PQ評価 3色円。Git 管理外）で見えたこと：
  - 黒の画素の deg2 は「小さな値」とは限らない（PNG の 3色円で多くは 0.99 前後、0 の画素もある）
  - 黒の画素を除くと、PQ評価の deg2 は 1.0002〜1.0004 のような狭い範囲。0〜1 では真っ白で、面内最小〜最大でないとムラが見えない
  - 動画（mp4）では圧縮で色の境目に小さな階調（1〜7）がにじむ。その画素は黒の画素に入らず、deg2 が低め（R で最小 ≈ 0.49）で、
    面内最小〜最大の範囲を決めてしまう → 担当者の画面確認で扱いを決める（チェックリスト E-1）
