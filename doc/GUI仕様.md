## 1. 用語

| 用語 | 意味 |
|---|---|
| **レシピ (recipe)** | 1つの処理ステップの定義。入力ファイル参照、Simパラメータ（表示条件を含む）、初期ストレス設定を持つ。名前を持つ |
| **パネル設定** | パネルの特性。シーケンスに1組（フェーズF）。**機種ごと**＝マスターモデル（`degparam_mm`：N・K0・Q・B0・A）とサブモデル（`degparam_sm.csv`）、**個体ごと**＝BC設定（`bcsetting.csv`：Band・GI_LUT・Duty など） |
| deg1 / deg2 | deg1＝基準の電流密度での輝度残存率（出力 `deg`。マスターモデル）、deg2＝表示する電流と劣化の程度で決まる残存率（出力 `deg2`。サブモデル）。画像には deg1×deg2 をかける |
| **実行シーケンス (sequence)** | どのレシピをどの順番で実行するかを決めたもの。名前を持つ。＝実行シーケンスConfig |
| **アプリConfig** | アプリ全体の設定（ログ容量など）。実行シーケンスとは別ファイル |
| Aging | 入力（動画または静止画）を表示し続けてパネルを劣化させる処理（ストレスを貯める） |
| PQ評価 | 入力（静止画または動画）を、蓄積した劣化状態のパネルに表示したときの見え方を作る処理（ストレスを貯めない） |
| ステップ種別 | レシピごとに Aging / PQ評価 を**手動で選ぶ**（2026-10-19 変更。以前は入力の拡張子で自動判定） |

## 2. 全体構成

- Python / PySide6、5タブ（① フォルダ設定 / ② 実行ステップ / ③ ステップ設定 / ④ 実行 / ⑤ 結果）
- 劣化計算コアは `source/` 側。GUIは**I/F固定で差し替え可能**な形で分離する
  （2026-11-18 から新コア：松井さん `Burn_in_sim_core_01`。bisim は `burn_in_band_extract`（Band 選択。ステップの開始時に1回）と
  `burn_in_core`（1フレーム）を呼ぶ。`engine.CoreModel`）
- モデル/Simパラメータは**CSV経由で `source/` のCLI版と互換**を保つ（IP設計者がGUIと独立にコアを改良・CLI実行できるように）
- リリースは英語UI。日本語UIは開発者用に残す（`prototype/i18n.py` 相当）
- 明るいグレー基調に固定

## 3. Config（3種・すべて JSON）

### 3.1 アプリConfig

アプリのあるフォルダに配置。

| キー | 内容 |
|---|---|
| `log_max_mb` | `_log_BISim/` の総容量上限 [MB] |
| `language` | UI 言語（`ja` / `en`） |
| `default_folders` | 直近使用した6フォルダ。新規シーケンスの初期値に使う（存在するパスのみ採用） |

### 3.2 実行シーケンスConfig

| キー | 内容 |
|---|---|
| `sequence_name` | 実行シーケンス名。出力ファイル名の先頭に使う |
| `folders` | 入力画像／ヒートマップ／BC設定／モデル／Sim／出力 の各フォルダ。**相対パスも可**：基準は **BI-sim.exe のフォルダ**（開発環境の `python -m bisim` ではリポジトリ直下＝`paths.APP_DIR`）。開いたときに絶対パスへ読み替え、保存時は絶対パスで書く。書かれていない欄はそのPC（EXE）の既定フォルダ（2026-10-22 追加：基準フォルダの下に同じ構成でデータを置けば、別PCでもパスを書き換えずに開ける。実行条件は `tools/README.md`） |
| `panel` | パネル設定（フェーズF）：`bcsetting`・`degparam_sm`（ファイル名。フォルダは `folders` の BC設定・モデル）、`model_param`（mm の数値 `{N,K0,Q,B0,A: [R,G,B]}`）、`model_param_csv`（表示用）。**無い旧 JSON** は開いたときに標準ファイル（`source/dbi_conf/`）を割り当て、mm は1番目のステップの値（ステップごとに違えば警告） |
| `recipes` | レシピの順序付きリスト（各要素は 3.3 の内容、または保存済みレシピへの参照） |
| `stops` | 停止状態（7.1）。NN文字列キー。空なら JSON に出さない |

- メニュー「開く」「保存」で Load / Save
  - ファイル名は常にシーケンス名（サニタイズ後）＋ `.seq.json`
  - 「保存」：シーケンス名を変えていれば、新しい名前で保存して旧ファイルを消す（＝リネーム）
  - 「名前を付けて保存」：選んだファイル名をシーケンス名にして別ファイルとして保存する。**元のファイルは残す**
    （2026-10-22 修正。以前は元のファイルも消していた）
- 番号（NN）はリスト内の位置から算出、Config自体には保持しない（アプリ内部で持つ）

### 3.3 レシピ（単体でも保存・再利用可）

| キー | 内容 |
|---|---|
| `recipe_name` | レシピ名。入出力ファイル名に使う |
| `input_image` / `heatmap` | ファイル名（フォルダは 3.2）。`heatmap` は `heatmap_mode="fixed"` のとき空でよい |
| `heatmap_mode` | `file`（ヒートマップ指定） / `fixed`（ヒートマップなし・パネル全面固定温度） |
| `fixed_temp_c` | `heatmap_mode="fixed"` のときのパネル全面温度 [℃] |
| `sim_param` / `sim_param_csv` | インライン値 ＋ 参照CSVファイル名（両方保持）。`AGING_TIME`・`ACCEL_RATIO`・`TMP_L`・`TMP_H`・表示条件 `DBV_NIT`（既定 2000）・`DPK_ON`（0/1、既定 0）・`GADJ`（[R,G,B]、既定 1,1,1）。CSV は新コアの `simconf.csv` と同じ書式（旧形式の4項目だけの CSV も読める） |
| `sm_override` | このステップだけ使うサブモデル（任意。空＝シーケンスの sm）。モデルフォルダ内はファイル名、外は絶対パス。表示（deg2）にだけ効き、stat には影響しない |
| （廃止）`model_param` | フェーズF でパネル設定（3.2 `panel`）へ移した。レシピ単体の保存には mm は入らない |
| `init_stress` | `none` / `prev`（前レシピのstat継承） / `file`（指定） |
| `init_stress_files` | `file` のときの参照名 |

## 4. ファイル命名規則

`種別` = `deg` / `deg2` / `stat` / `movie` / `image` / `model-param` / `sim-param` …
`色` = `r` / `g` / `b`（**`deg` / `deg2` / `stat` のみ**。`movie` / `image` / `model-param` / `sim-param` は色なし単一ファイル。`w` は作らない）
`deg2` はフェーズF で追加（サブモデルの残存率。動画は最後のフレームの値。黒の画素も計算結果のまま）

- `model-param` / `sim-param` は CLI版（`source/` の `degparam_mm.csv` / `simconf.csv`）と同一書式の単一ファイル。`degparam_mm.csv` は「1行 `N,r,g,b`」、`simconf.csv` は「1行 `KEY,値`」。

| 区分 | 規則 | 例 |
|---|---|---|
| **入力** | `レシピ名_種別[_色].拡張子` | `aging01_movie.mp4` / `aging01_model-param.csv` / `pq01_stat_r.csv` |
| **出力（通常完了）** | `シーケンス名_NN_レシピ名_種別[_色].拡張子`（NN＝シーケンス内通し番号 2桁） | `SEQ_A_01_aging01_deg_r.csv` / `SEQ_A_01_aging01_movie.mp4` |
| **停止チェックポイント** | `<出力>/_stops/<シーケンス名_NN_レシピ名>/` に素のファイル名（7.1） | `_stops/SEQ-A_01_aging01/stat_r.csv` / `.../movie.mp4` |

- Input と Output で規則を変える理由：レシピ間で入力（共通パラメータ等）を共有し得るため、Inputはシーケンス非依存にする
- 前レシピの `stat` を次レシピが継承する場合、参照名は前レシピの**Output名**
- 出力ファイル名トークン `deg` は維持（UIラベルのみ「輝度残存率(1-劣化率)」に変更。IP設計者レビュー3）

## 5. タブ別仕様

### ① フォルダ設定
- 6種のフォルダをパス欄＋「参照…」（フォルダダイアログ）で変更。既定値は `source/` の構成
  （BC設定・モデル＝`source/dbi_conf`、Sim＝`source/dbi_input`）
- ③でファイルを選ぶと、その親フォルダがここに反映される
- **パネル設定（シーケンスに1組）**（フェーズF）：
  - 機種（劣化モデル）：マスターモデルの表（mm。直接編集＋CSV 読込/保存。入力するとすぐシーケンスへ）、サブモデルのファイル（モデルフォルダ）
  - 個体（BC設定）：BC設定のファイル（BC設定フォルダ）
  - ファイル欄ごとに検査結果（✓／✗＋問題点）、「**Excel で開く**」（選んでいるファイルをそのまま開く。複製・名前の付け方はユーザーに任せる）、「再検査」
  - **検査はキー名と行数・列数だけ**（値の並び順・軸の端の値は見ない。軸の並びのきまりは説明文に書く）。
    ファイルが変わったら（Excel で保存したら）**自動で検査し直す**（ファイルとフォルダを監視）
  - 実行の前に、パネル設定のファイルが変わっていたらモデルを作り直す（ファイルの更新時刻・大きさで判断）

### ② 実行ステップ
- レシピの一覧表示。**追加 / 複製 / 削除 / 並べ替え**
- **ファイル指定は不可**（詳細は③）。ここは順序操作のみ
- ②で空行を追加 → ③で設定、という流れ（②③の順序はこのまま）
- **停止中のステップがあるとき**に削除・複製・並べ替えをすると確認を出す（2026-10-22）。停止状態は
  ステップの番号（NN）で覚えているため、番号がずれると別のステップに付いてしまう。続ける場合は
  停止状態と `_stops/` の途中結果を破棄し、シーケンス JSON に反映する。末尾への追加は番号が変わらないので確認しない

### ③ ステップ設定
- 選択中レシピを編集
- **ステップ種別**（2026-10-19 変更。議事録 261015 の指摘1への対応）：Aging / PQ評価 を手動で選ぶ。
  入力が動画か静止画かとは独立。②の Type 列にも表示する
  - **Aging × 動画**：従来どおり（1フレーム = (1/fps) × ACCEL_RATIO）
  - **Aging × 静止画**：同じ絵を **fps=1** で繰り返す（1フレーム = 1秒 × ACCEL_RATIO）。回数は AGING_TIME で決まる
    （`0` なら1フレーム）。出力は最後の劣化画像（PNG）。停止・再開も可
  - **PQ評価 × 静止画**：ストレスを貯めずに劣化後の画像を1枚作る（従来どおり）
  - **PQ評価 × 動画**：ストレスを貯めずに全フレームを1周回し、劣化後の見え方の動画を作る
  - PQ評価では**ヒートマップ（温度）欄と、Sim条件のうち Aging 条件の行（ACCEL_RATIO・TMP_L/H・AGING_TIME）を隠す**。
    表示条件（DBV_NIT・DPK_ON・GADJ）は出したまま（フェーズF）。温度設定なし
    （内部は 25℃ 固定＝`engine.EVAL_TEMP_C`。A=0 なら結果に影響しない）
  - 種別の欄が無い旧シーケンス JSON は、読み込み時に拡張子から決める（`.png`→PQ評価、それ以外→Aging）。従来どおりの動作になる
- **画像サイズの検査**（2026-10-19 追加。議事録 261015 の指摘2への対応）：入力画像・ヒートマップを選んだ時点で、
  シーケンスの**基準サイズ**と比べ、違えば注意メッセージを出して**選択させない**
  - 基準＝シーケンス内で最初に見つかる画像（ステップ順に 入力画像 → ヒートマップ。通常はシーケンスの最初に選んだ画像）
  - 動画・静止画の別は問わない。ヒートマップは実際に使う場合（Aging・ファイルモード）だけ基準に数える
  - 選び直している欄そのものは基準から除く
- プレビュー3面：入力画像 / ヒートマップ / **前ステップの画像**（初回・継承なしは非表示。
  2026-10-19 に「前回Aging結果」から文言変更。議事録 261015 の指摘3）
- **ヒートマップなし（固定温度）**（IP設計者レビュー2 (2)）：チェックボックス＋数値入力（℃）。
  チェック時はヒートマップファイル欄を無効化し、パネル全面をその温度として計算する
  （ヒートマップ画像・動画は不要。プレビューは「固定温度 XX℃」表示に置き換え）
- 初期ストレス：なし / 前ステップ継承 / ファイル指定
- （モデルパラメータ表はフェーズF で①のパネル設定へ移した）
- Sim条件（ACCEL_RATIO, TMP_L, TMP_H, AGING_TIME）＋ 表示条件（DBV_NIT・DPK_ON・GADJ R/G/B。フェーズF）。CSV 読込 / 保存
- **サブモデルの差し替え**（任意。フェーズF）：「このステップだけ別のサブモデルを使う」チェック＋ファイル欄＋「参照…」＋「Excel で開く」＋検査結果。
  選んだ・外した時点でレシピに反映（「適用」不要）。表示（deg2）にだけ効く
  - **AGING_TIME**（IP設計者レビュー2 (3)）：Aging の**目標時間**[秒・整数]。`0`＝無制限（動画を1周回のみ処理）。
    正の値のとき、1周回の加速込みAging実時間（`frames_total/fps × ACCEL_RATIO`）と比較し、
    - 実時間が目標を**超える** → 目標に達した時点で打ち切り（フレーム境界。最低1フレームは処理する）
    - 実時間が目標に**満たない** → 動画の先頭へ戻って周回し、目標に達するまで継続。出力動画は全周回を連結
    - 静止画 Aging は fps=1 として同じ規則（1フレーム = 1秒 × ACCEL_RATIO）。PQ評価ステップは AGING_TIME を使わない
- 処理パイプライン（BIP・DBI補正・ピーク輝度制御）・A/B比較 … 将来枠・無効表示（BC設定はフェーズF で①のパネル設定に入った）

### ④ 実行
- **実行中（一時停止中を含む）は ①②③タブとメニューの「開く・保存・名前を付けて保存・レシピ読込/保存」を使えない**
  （2026-10-22）。実行の途中でパラメータやステップ構成が変わると結果が壊れるため。④⑤と言語切替は使える。
  実行が終わる・停止する・エラーで止まると元に戻る
- ボタン：**全ステップ実行** / **実行するステップを選択**（単一選択） / **中断・再開** / **停止**
  - 中断・再開：メモリ保持、**ファイル出力なし**。同一起動中に再開
  - 停止：**保存要否をユーザーに確認** → 保存する場合はチェックポイント出力＋シーケンスJSONに停止状態を内包（7.1）。後で「シーケンスを開く」→「▶↻ 停止位置から再開」で継続
- **選択中レシピの動画情報**（評価メモ #1）：動画Agingレシピを選ぶと、総フレーム数・fps・
  ネイティブ長さ・現在の ACCEL_RATIO での1周回のAging時間に加えて、**現在設定中の AGING_TIME の値と、
  それが「無制限／打切り／周回」のどれになるか＋見積りフレーム数**を表示する。③で AGING_TIME を
  変更して「この設定を適用」すると、この表示がそのまま追従する（静止画 Aging は fps=1 での見積り、
  PQ評価ステップは「Aging しない」の表示）。
  **注意**：ACCEL_RATIO が大きいほど1フレームあたりの加速込み時間も大きくなるため
  （既定 ACCEL_RATIO=30000・30fps なら約1000秒/フレーム）、AGING_TIME がそれより小さい値は
  どれも「最低1フレーム」に丸められ、結果が区別できなくなる。見積りフレーム数の表示で確認できる
- 進捗：全体（step i/N）＋ フレーム（j/M）＋ 処理中フレームのライブ表示
- 時間表示：
  - **計算時間**：実PC計算時間（現状）
  - **Aging時間（加速込み）**：`(処理フレーム数 ÷ fps) × ACCEL_RATIO` をステップ内＋シーケンス累積で。
    表示は時:分:秒（例 `00h 00m 10s`。24時間超は日数も付記、例 `4d 04h 00m 00s`）。
    小さい ACCEL_RATIO 等で秒単位の値になっても見えるよう、時間の小数（`0.00 h`）表示はしない（評価反映3 B-3）
- ログ：画面表示 ＋ ファイル出力（6章）

### ⑤ 結果
- 表示する idx を選択
- **劣化後プレビュー**：画像／動画（動画はフレームスライダ。フレーム番号に加速込み Aging 時間〔実行内の前ステップ累積込み〕を併記）
- **輝度残存率マップ**：R / G / B / RGB合成。各チャネル色の輝度表示（**明るい＝劣化していない**）
  - **表示する量の選択ボタン**（フェーズF）：deg1（基準電流密度。`_deg_{c}.csv`、既定）／deg2（サブモデル。`_deg2_{c}.csv`）／
    deg1×deg2（画像にかけた値。表示時に2つの CSV の積。ファイルは増やさない）。deg2 の無い結果（フェーズF より前の停止結果）では deg2 系を押せない
  - **スケール**：「0 〜 1（1 超は 1）」（既定）／「面内最小 〜 面内最大」（3つの量で共通）
  - **黒の画素**：deg2・deg1×deg2 では、最後に処理した入力フレームでその色が 0 の画素を灰色で表示し、表示範囲と統計から除く
    （黒は電流 0 で表の範囲外になり、意味のない値になるため。deg1 は除かない。ファイルには出さない）
  - 注記：deg1×deg2 が画像にかけた値と完全に一致するのは PQ評価（dt=0）かつ A=0 のとき。Aging ステップでは最終フレームの分だけずれる。
    別の画像の結果どうしの比較は deg1 を使う
  - 見出しは2行（1行目＝何のマップか、2行目＝表示範囲）
- **累積時間マップ**（`_stat_{r,g,b}.csv`）：同上。**R/G/B各色ごとに自分の最大値で正規化**し
  **明暗反転（暗い＝累積大）**（評価反映3 B-2。チャンネル間で最大値の桁が大きく異なると
  共通基準では小さい方が常に明るいまま埋もれて反転が分かりにくくなるため、各色独立に正規化する）
  - **スケールの切替**（2026-10-23。Excel No.9／10/15 MTG 指摘4）：「0 〜 面内最大」（既定・従来）と
    「面内最小 〜 面内最大」を選べる。後者は前ステップからの引き継ぎで全面が底上げされていても、
    その上のムラ（焼き付きの差）が見える。各色ごとに正規化・明暗反転は同じ。表示のみで CSV は変わらない。

## 6. ログ

- 場所：アプリのあるフォルダ直下 `_log_BISim/`（無ければ作成）
- 方式：**セッションローテーション**（IP設計者レビュー2 (1)）。アプリ起動ごとに新しいファイル
  `BISim_YYMMDD-HHMMSS.log`。1ファイルの大きさ感は従来の日次ログと同程度に保つため、
  同一セッション中でもファイルが `log_max_mb` に達したら `..._02.log` `..._03.log` … と継続する
- 総容量が `log_max_mb`（アプリConfig）を超えたら古いファイルから削除（従来どおり）
- 内容：入出力ファイル名、実行した動作、パラメータ変更 など（簡潔に）

## 7. 停止・中断・再開の状態遷移

```
実行中 ──中断──▶ 中断状態（メモリ保持・ファイルなし）──再開──▶ 実行中
実行中 ──停止──▶ 保存する？ ──Yes──▶ チェックポイント出力＋シーケンスJSONに停止状態を内包──▶ 終了（後で継続可）
                              └─No───▶ 終了（破棄）
```

### 7.1 停止状態はシーケンスに内包する

- 停止（＝再開）情報は**そのシーケンス固有**なので、実行シーケンスConfig（3.2）が
  `stops` キーで内包する。別ファイル（サイドカー）は作らない。

  ```json
  "stops": {
    "01": {
      "recipe_name": "aging01",
      "frames_done": 42, "frames_total": 405,
      "aging_seconds": 12345.6, "is_movie": true,
      "timestamp": "260909-1030",
      "dir": "_stops/SEQ_01_aging01"
    }
  }
  ```

  キーは NN（ステップ位置。2桁）。空なら JSON に出さない。
- チェックポイント実体は **`<出力フォルダ>/_stops/<シーケンス名_NN_レシピ名>/`** に
  素のファイル名で置く：`stat_{r,g,b}.csv` / `deg_{r,g,b}.csv` / `deg2_{r,g,b}.csv`（フェーズF。再開には使わない） / `movie.mp4`（動画時）。
  **日時なし・常に最新1件**（同じステップを再停止したら上書き）。
- 停止して「保存する」を選ぶと、チェックポイント書き出しに続けて
  **シーケンスJSONを自動保存**する（保存先が未定なら「名前を付けて保存」を促す）。
- 再開の導線は1本化：
  - 同一起動中 … ④実行タブ「▶↻ 停止位置から再開」ボタン（対象ステップ選択時に有効）
  - アプリ再起動後 … 「シーケンスを開く」で `stops` が読み込まれ、同じボタンが有効になる
- 「停止位置から再開」が**通常完了**したら、`stops["NN"]` を削除しシーケンスJSONを更新、
  `_stops/<...>/` も削除する。フォルダがエクスプローラー等で開かれていて削除できなかった場合は
  ログとステータスバーで知らせ、残った**空の**フォルダはシーケンスを開いたときに削除する
  （中身の残っているフォルダは触らない。2026-10-22 追加）。
- 開いたシーケンスを別PCへ移すと `stops` は残るが `_stops/` 実体が無いため
  再開時に「停止チェックポイントが見つかりません」で失敗する（ローカル状態なので想定内）。
