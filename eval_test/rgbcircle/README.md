# 理論確認テスト（3色円）

bisim が劣化モデルの式どおりに計算しているかを、**絵と数値の両方で**確かめるためのテスト一式。

- Aging 用：黒背景に R/G/B の円を重ねた静止画を MP4 にしたもの（中央が白、重なりが黄・マゼンタ・シアン）
- 評価用：全面白の静止画
- パネル：横 240 × 縦 512 画素。円の半径 70px、中心間距離 70px（R=上、G=左下、B=右下）

## フォルダの中身

| パス | 内容 | 作るもの |
|---|---|---|
| `input/rgbcircle-aging_movie.mp4` | Aging 用動画（mp4v・30fps・30フレーム＝1秒。全フレーム同じ絵） | `tools/make_rgbcircle_test.py` |
| `input/rgbcircle-eval_image.png` | 評価用の全面白画像 | 同上 |
| `input/rgbcircle-pattern.png` | 参考：MP4 にする前の理想の絵（画素値は 0 か 255 のみ） | 同上 |
| `input/rgbcircle-regions.png` | 参考：領域番号（数値の表を作るときに使う） | 同上 |
| `rgbcircle.seq.json` | bisim でそのまま開けるシーケンス（14ステップ） | 同上 |
| `theory/` | 理論値の表（画像・数値）と、bisim との比較結果 | `tools/rgbcircle_theory.py` |
| `output/` | bisim の出力先（シーケンスの出力フォルダ）。CSV が多く約 250MB になる | bisim |

## シーケンスの設定

| 項目 | 値 | 理由 |
|---|---|---|
| ACCEL_RATIO | 3600 | 1フレームの加速込み時間 ＝ (1/30秒) × 3600 ＝ **120秒**。動画1周回（30フレーム）が**ちょうど1時間** |
| 温度 | ヒートマップなし・固定 25℃ | 温度の影響を外す（全画素で同じ温度） |
| モデルパラメータ | 既定値（N/K0/Q/B0/A）＝ `source/dbi_conf/degparam_mm.csv` と同じ | |
| ステップ | Aging → 評価 を 7 回繰り返す（累積 0.5h／1h／2h／5h／10h／20h／50h） | 1本のシーケンスで全行の結果が出る |

- 01 だけ初期ストレス「なし」。02 以降はすべて「前ステップ継承」。
- 評価ステップ（静止画）は Aging しない（dt＝0）ので、次の Aging は評価前と同じ累積ストレスから続く。
- 各 Aging の AGING_TIME は「前の行からの増分」（例：03 は 0.5h→1h なので 1800秒）。
- 01（0.5h）は動画の途中（15フレーム）で打ち切り、05 以降は動画を周回します。どちらも AGING_TIME の処理の確認を兼ねています。
- 暫定パラメータは劣化がかなり速く、1時間で R は 0.73、B は 0.34 まで下がり、50h でほぼ黒になる。そのため行は 50h までにしています。

## 手順

1. （作り直すときだけ）入力を作る：`.venv\Scripts\python tools\make_rgbcircle_test.py`
2. 理論値を計算する：`.venv\Scripts\python tools\rgbcircle_theory.py`
   → `theory/rgbcircle_theory_table.png`（表の画像）、`theory/rgbcircle_theory_values.md`／`.csv`（数値）
3. bisim で実行する：`python -m bisim` → メニュー「シーケンスを開く…」で `rgbcircle.seq.json` → ④実行タブ「▶ 全ステップ実行」（約40秒）
4. 比較する：`.venv\Scripts\python tools\rgbcircle_theory.py --compare`
   → `theory/rgbcircle_compare.md`（全14ステップの差と判定）。表の画像に「bisim：評価画像」の行が追加される

GUI でパラメータを変えて試すときは、シーケンスを保存してから手順 2・4 を流す。理論計算はシーケンス JSON の値を読むので、変えた値で計算し直されます。
対応しているのは固定温度モードと、初期ストレス「なし／前ステップ継承」だけです。
別PC（EXE）で実行した場合は、出力フォルダを `--bisim-out <フォルダ>` で指定します。

## 理論値の計算（`tools/rgbcircle_theory.py`）

劣化コア（`source/main.py`）は**使わず**、モデル式から独立に計算する。1フレームごとに次を繰り返す：

```
deg  = exp( -stat ^ β )                          β = B0 + A·T（A=0 なので β = B0）
lum  = (画素値/255)^2.2 × deg                    劣化した後の明るさ（0〜1）
stat = stat + Δt × ACCEL_RATIO × lum^N / (K0 × exp(Q/T))
```

評価（白）では `評価画像の画素値 = floor( 255 × deg^(1/2.2) )`。

**数値例（R が点灯している画素、1時間＝30フレーム）**：N=1.5、K0=500、Q=1000、B0=0.7、T=298K
- 1フレームで貯まる量（劣化していないとき）＝ (1/30)×3600 / (500×exp(1000/298)) ＝ 120 / (500×28.67) ＝ **0.00837**
- 1フレーム目：deg＝1 → stat＝0.00837
- 2フレーム目：deg＝exp(−0.00837^0.7)＝0.965 → 明るさが下がった分だけ貯まり方が遅くなる（0.00837×0.965^1.5）→ stat＝0.01632
- 30フレーム目まで繰り返すと stat＝0.1906、deg＝exp(−0.1906^0.7)＝**0.731**
- 白で評価すると 255×0.731^(1/2.2)＝221.1 → **221**（表の 1h・R の値）

注意点：
- **劣化した後の明るさでストレスを貯める**。劣化するほど貯まり方が遅くなるので、「時間×一定量」の単純な掛け算にはならず、1フレームずつ計算する必要がある。
- **MP4 は非可逆**で、画素値が理想の 0/255 から数階調ずれる（円の縁では大きくずれる）。
  理論計算には**動画から読み出した画素値**を使うので、bisim と同じ入力で比較できる。
  表の「理想値」は画素値＝255 として計算した教科書どおりの値です。
  「領域ごと」の値（実際の動画から計算）は、理想値と数階調ずれることがあります（例：1h の R は理想値 221、領域内は 221〜224）。
- 消灯している色（例：R の円の中の G・B）は劣化しない（deg＝1、評価値 255）。これで**色ごとの独立性**も確認できる。

## 2026-10-19 の確認結果

GUI と同じエンジン経路（`engine.run_sequence` → `write_recipe_outputs`）を画面なしで流し、
`--compare` で比較した結果は次のとおり。

- **全14ステップで stat・deg・評価画像とも理論値と完全一致（差 0）**
- 比較が働いているかの確認：理論側の K0(R) をわざと 1% ずらすと、R だけが NG になる（G・B は差 0 のまま）
